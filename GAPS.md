# GAPS

Deliberate incompleteness and missing infrastructure. A gap is closed only by evidence, never by a stub. Each row names the evidence that closes it and the plan item that produces it. IDs are never reused: a closed gap's row is removed and its ID retired. `make check-docs` verifies that every cited work package and phase exists.

| G-001 | FND-01 delivered the command contract and the scaffold; FND-03 added the conventions: the shared error envelope and schema validation for REST, the WebSocket command and event envelopes with the version counter, and the redacting logger. SRV-01 added the schema of the eight entities (migration 0001) and their contract types in `shared`. SRV-02 added the PIN, DM sessions, the lockout and the session guard on every `/api` route, with `/api/auth`, `/api/setup`, `GET /api/settings` and `PUT /api/settings/pin` (D-076); no other entity is read or written yet: there is no other REST resource, no WebSocket server or room, and no command payload schema, so the process command validator refuses every command as `command_unsupported` until LIV-01 onward register payload schemas (D-064). FND-04 made the views shells: the DM view at `/dm` is a banner, a skip link and a main landmark with no workspace (PRP-01), and the player view at `/` is the idle screen, which never switches to a live scene and does not hide the cursor yet (LIV-03). The CI pipeline of FND-02 runs every gate on Linux and Windows. | G-003 | On Windows, CI runs the gate targets (`lint` to `scan-secrets`) through MSYS2's `make` and bash and they pass (FND-02, D-060), but `make dev` and `make clean-start` are not in CI: `scripts/clean-start.sh` uses `setsid` and `tar`, which Windows has only through MSYS2, Git Bash or WSL, and macOS lacks `setsid`. | A Windows developer may be unable to run `make clean-start` or `make dev` as written; the server itself is plain Node and runs natively (the Windows `e2e` job starts it with `npm start`). | A recorded run of `make dev` and `make clean-start` on Windows, or a recorded decision on how Windows runs them. | REL-02 |
| G-007 | The views have no loading, reconnecting or load-failure state. `client/src/main.tsx` renders nothing until the view's chunk arrives, and a chunk that fails to load (the server stopped, or restarted with a new build between the page and its script) leaves the dark background with an unhandled rejection and no message. The error boundary covers only a view that throws while rendering, and the DM error screen's Reload button is tested by click in jsdom, not by the keyboard gate, because the production build has no way to make a view fail. Found by the FND-04 review, 2026-09-24. | A DM whose laptop loses the server mid-load sees a blank page with no way out but the browser's reload; the TV shows the dark idle background, which is harmless. | A loading and a load-failure state for both views, and the reconnecting state of `04` §6, each rendered from the catalogue and covered by tests; the DM's failure state reached and operated in the keyboard smoke test. | LIV-01 |
| G-008 | Every database backup (`09` §2) keeps the PIN hash that was current when it was taken, including one from before a `reset-pin` or a PIN change.

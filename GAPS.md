# GAPS

Deliberate incompleteness and missing infrastructure. A gap is closed only by evidence, never by a stub. Each row names the evidence that closes it and the plan item that produces it. IDs are never reused: a closed gap's row is removed and its ID retired. `make check-docs` verifies that every cited work package and phase exists.

| G-007 | The views have no loading, reconnecting or load-failure state. `client/src/main.tsx` renders nothing until the view's chunk arrives, and a chunk that fails to load (the server stopped, or restarted with a new build between the page and its script) leaves the dark background with an unhandled rejection and no message. PRP-01 part 1 gave the DM view one state of its own: while it asks the server whether a PIN exists and whether it is signed in it says it is loading, and when that request fails it names the reason and offers Try again (D-085); a chunk that fails to load, the player view and reconnecting are still open. | G-010 | The lockout of `07` §6 is per client address (Q-009), so a LAN client that changes its IPv4 address gets 5 fresh guesses per address: about 1,250 in the first minute from a /24, and a 4-digit PIN within hours. Found by the SRV-02 review, 2026-09-24. | A determined device on the Wi-Fi can still guess a short PIN in one evening. | An owner decision (a question card: a server-wide failure budget, IPv6 keyed by /64, or the accepted residual risk stated in the README), then its test. | REL-01 |

| G-017 | Upload residuals the SRV-04 review deferred, each open only to a DM session or to the DM's own PC. Found by the SRV-04 review, 2026-09-24. | On a slow link an oversized map takes long to refuse, or ends in a network error; a DM can fill the disk only by uploading; two servers on one data directory lose an upload in flight, not stored data. | The asset dialog shows its upload's progress through `upload(file, onProgress)` as the scene map does, with a component test, or a recorded decision that asset images are small enough not to need it; a `checkContinue` handler answering 413 before the body for a declared length over the limit, with a real-connection test; the README (REL-01) states one server per data directory and that the images folder grows with uploads; or a recorded decision that accepts them. | REL-01 |
